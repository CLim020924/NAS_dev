# NAS UI Design System

이 문서는 NAS 플랫폼의 웹 UI와 앞으로 추가될 앱이 같은 인상을 유지하기 위한 최소 규칙이다. 전역 구현의 단일 기준은 `frontend/src/contexts/ThemeContext.js`다.

## 방향

- 장식보다 정보 구조와 상태 구분을 우선한다.
- 큰 둥근 모서리, 과한 그림자, 호버 시 위치 이동을 사용하지 않는다.
- 색은 주요 행동, 선택 상태, 경고와 연결 상태처럼 의미가 있을 때만 사용한다.
- 같은 역할의 요소는 모든 앱에서 같은 높이, 모서리, 포커스 표현을 사용한다.

## 기본 규격

| 요소 | 규격 |
| --- | --- |
| 버튼·입력창·메뉴·목록 | 4px 모서리 |
| 창·대화상자 | 6px 모서리 |
| 상태 점·아바타·진행 표시 | 의미상 원형 허용 |
| 기본 테두리 | 테마 `divider` 1px |
| 호버 | 배경색 또는 테두리색만 120ms 내 변경 |
| 포커스 | `:focus-visible` 2px 외곽선과 2px 간격 |
| 그림자 | 떠 있는 창과 메뉴에만 낮은 강도로 사용 |

## 새 기능 구현 규칙

1. 일반 버튼은 MUI `Button`을 그대로 사용하고 개별 `borderRadius`, `boxShadow`, `transform`을 추가하지 않는다.
2. 카드와 목록은 `Paper variant="outlined"` 또는 1px 테두리를 기본으로 한다.
3. 선택 상태는 테두리와 옅은 배경색으로 함께 표시하며 색만으로 구분하지 않는다.
4. 호버 시 `translate`, 확대·축소, 지속 애니메이션을 사용하지 않는다. 연결 중 상태처럼 실제 상태 전달에 필요한 애니메이션만 허용한다.
5. 화면 내부에서 새 색상·간격·모서리 규칙을 만들기 전에 전역 테마를 재사용한다.
6. 라이트·다크·오션 테마와 키보드 포커스를 모두 확인한다.
7. 모바일의 원형 빠른 작업 버튼처럼 사용 맥락상 필요한 예외에는 접근 가능한 이름을 제공한다.

## 검수 항목

- 버튼, 입력창, 메뉴, 카드의 모서리가 같은 계열인가
- 주요 행동과 보조 행동의 대비가 명확한가
- 호버 전후에 요소 위치가 움직이거나 깜빡이지 않는가
- 키보드만으로 현재 포커스를 확인할 수 있는가
- 색을 보지 않아도 선택·경고·연결 상태를 이해할 수 있는가
- 360px 모바일 폭과 일반 데스크톱 폭에서 내용이 잘리지 않는가
